## Implementation Notes

- **This is the hard part of phase 3.** An id of `<incident id>:<update timestamp>` means
  editing the wording of an update keeps its identity, while correcting a *time* creates a
  new entry.
- That trade is deliberate. A content hash would make every typo fix a fresh notification,
  which is worse, and is the obvious-looking wrong answer.

## Acceptance Criteria

- [ ] Rewording an update does not change its id
- [ ] Changing an update's time does
- [ ] The behaviour is documented where an author will see it

## Testing Strategy

- **Unit:** render the feed, edit the body, render again, assert the id is unchanged.
