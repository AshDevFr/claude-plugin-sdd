## Implementation Notes

- **The ordering is the product decision in this phase.** Open before resolved, then newest
  first. A reader arriving during an outage wants the thing that is broken now.
- The first version sorted purely by date and buried an open outage under a week of resolved
  incidents. That is the bug this task exists to have already fixed.

## Acceptance Criteria

- [x] `load` returns every incident in the file
- [x] A duplicate id raises
- [x] Open incidents come first
- [x] Resolved incidents are newest first among themselves

## Testing Strategy

- **Unit:** `LoadFile` asserts the two-level ordering against the example file.
- **Integration:** the example file is the one the CLI tests and the demo use, so it cannot drift.
