## Implementation Notes

- **`check` exits 1 while an incident is open**, so a deploy pipeline can refuse to ship
  into an outage. That is the reason the command exists at all.
- Exit 2 is reserved for a bad file or a missing one, so a pipeline can tell "we are in an
  incident" from "your incidents file is broken".
- `IncidentError` and `OSError` are caught and printed; a traceback is never the output.

## Acceptance Criteria

- [x] `check` exits 1 with an open incident, 0 with none
- [x] A malformed file exits 2
  and explains
- [x] `render -o -` writes to stdout
- [x] `--title` reaches the page

## Testing Strategy

- **Unit:** `Check` and `Render` drive `main()` with redirected streams, so no subprocess.
- **Integration:** render to a temp file and assert the file's content.
